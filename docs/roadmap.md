# 路线图

近期主线是把经典 NMOS 6502 CPU 做得更可靠、更容易定位问题，并逐步提高总线和中断时序精度。**M2 专注 CPU，Apple I 为独立里程碑。** M2.1～M2.5 的本地目标范围已完成验收，包含物理 RESET 的全部固定对照；范围限定为官方指令、记录的引脚窗口和固定 revD 假设，不把本地结果等同于远程 CI 或任意芯片修订认证。

## 已完成的基线

- [x] **M0：可运行 CPU 最小系统**。两个 Cargo crate；独立 CPU／Bus／RAM；25 个指定 opcode；复位向量启动的原创演示；trace、有限步数、自包含测试；架构、支持清单、验证记录和最小 CI 配置。本地验收完成，结果见 [verification.md](verification.md)；远程 CI 尚未执行。
- [x] **M1：完整 NMOS 官方指令与指令级中断**。151 个官方 opcode／56 条指令及全部官方寻址方式；ADC/SBC 二进制与十进制运算（含 NMOS 特有标志）；BRK/RTI、IRQ/NMI 的指令边界采样、状态压栈、优先级和返回。支持清单逐项对应测试；57 个本地测试在 debug/release 下通过，见 [验证记录](verification.md)。这是按指令模型范围内的完成，不表示逐相位中断兼容或整个外部套件通过。

## M2：CPU 一致性、总线时序与可调试性

- [x] **M2 本地整体验收**。M2.1～M2.5 的固定目标范围已在最终执行器上复验，CPU／CLI 保持可运行。先建立独立预期与失败诊断，再修改执行模型；实际命令和结果见 [验证记录](verification.md)。远程 CI、提交、推送和发布是独立状态。

### M2.1：可复现的外部测试入口（已完成）

- [x] 在现有 CPU 测试中接入 SingleStepTests 原始 JSON 格式，恢复原始 PC、寄存器和 RAM，比较执行后的寄存器、内存与 `cycles` 数量。P 的位 4/5 按已有表示约定规范化并记录原因，不屏蔽六个存储标志。总线序列比较明确标为尚未验证。
- [x] 首批固定 21 个 opcode：`EA 0A A9 A5 B5 B6 AD BD B9 6C A1 B1 D0 00 40 69 E9 9D FE 20 60`，各取对应文件原顺序前 32 条，共 672 条。它们覆盖全部寻址方式，以及算术、分支、栈、中断指令、索引写入和 RMW；保留现有 8 条十进制样例和本地边界测试。首批通过不代表这些文件全量通过。
- [x] 测试工具支持按 opcode／用例定位；失败时给出数据版本、用例名、初始状态、首个差异和可复现命令。校验输入范围、数据缺失、解析失败与实际执行数量，不能空跑后报告成功。

**验收**：672 条固定样例在 debug/release 下完成寄存器／内存和周期数量比较；发现的 CPU 差异有独立回归测试并修复。错误路径能准确定位，普通 `cargo test --workspace` 离线可运行。本阶段只建立验证入口及修复它发现的指令问题，不启动周期引擎改造。

### M2.2：官方指令与十进制运算的外部一致性（已完成）

- [x] 将 SingleStepTests 扩展到 **151 个官方 opcode 对应文件的全部用例**，按清单记录文件、用例数量和实际结果；这是 NMOS 官方指令子集的全量验证，不包括剩余非官方字节。
- [x] 接入固定版本 Klaus Dormann NMOS 功能测试。记录源码、汇编器版本／配置、镜像哈希、加载地址、成功地址和失败判据；使用宿主步数／周期预算，不能把任何自循环都判为成功。
- [x] 执行 Bruce Clark 十进制测试：`cputype=0`、`vld_bcd=0`，开启 A/N/V/Z/C 全部检查，覆盖有效和无效 BCD 的所有 A／操作数／C 组合；保留当前二进制穷举。宿主到达 `DONE` 后检查 `ERROR`，在执行结束宏前停止，不为上游结束字节添加 65C02 STP 或伪造 HALT。

**验收**：上述固定范围的寄存器／内存结果全部通过，SingleStepTests 周期数量全部通过，功能和十进制程序到达明确成功条件且未超限。对发现的差异先核对资料和原始数据、保留最小回归；不能改预期、跳过失败或忽略算术标志来通过。记录的芯片／资料差异必须明确影响范围，未解决的目标范围差异阻止本阶段完成。

### M2.3：真正逐周期的总线执行（已完成）

- [x] 把整条指令执行拆成内部阶段和必要的中间状态，提供真正每次推进一个 CPU 周期的接口；`step` 最终包装同一执行引擎，保留宿主按指令驱动的用法，不长期维护两套指令语义。具体接口在迁移首个指令族时确定，不先搭建通用微代码框架。
- [x] 按读指令 → 写指令／RMW → 分支／跳转／栈 → BRK/RTI/RESET 的顺序迁移，补齐 dummy read、索引中间地址访问、RMW 旧值回写及栈访问顺序。迁移每类后同时验证结果、周期数量和访问序列。
- [x] 测试 Bus 捕获每个周期的地址、读写和数据；加入带读取副作用的测试设备，验证真实访问会发生、日志不会增加访问。CPU 继续接收外部 Bus，设备推进和日志格式由宿主负责。

**验收**：151 个官方 opcode 的完整固定 SingleStepTests 子集通过逐周期总线比较；RESET 等无对应单步数据的路径有原始手册支持的独立访问测试。所有既有结果回归通过，`step` 的返回周期与实际推进周期一致，分次推进和连续推进结果一致。该阶段的总线精度不等于完成全部引脚相位精度。

### M2.4：中断、复位与外部引脚（本地已验收）

- [x] 在周期模型上替换现有指令边界近似，明确输入在哪个时钟相位采样、最短脉冲及同步规则；需要区分同一周期内的边沿时再引入相位调度，不能仅靠指令前／后 I 复现硬件流水线。
- [x] 逐项验证 CLI/SEI/PLP/RTI 及连续改写 I 的组合、分支末周期的采样差异、IRQ 电平、NMI 边沿与优先级、IRQ/BRK 被 NMI 抢占向量的窗口、RESET 对进行中指令／中断的影响。事件由宿主按周期／必要相位注入，记录具体位置和预期结果。
- [x] 依据 NMOS 原始硬件资料实现并验证 RDY 的等待／恢复、读写周期差异与 SO 边沿；测试等待期间的中断锁存与恢复，所有等待测试有周期预算。
- [x] 接入 Klaus 中断测试所需的测试 Bus 反馈寄存器；对精细窗口用 Visual6502 和原始硬件资料交叉核对，固定模型版本与芯片假设，不把单一修订的结果推广到所有 NMOS 芯片。

已落地：周期 IRQ/NMI 采样、分支轮询、向量抢占、246 个固定 revD trace，以及 Klaus 中断程序的显式延迟反馈入口。Klaus 4 周期额外延迟配置通过；0 延迟会触发上游已注明的真实 NMOS BRK/NMI 重叠陷阱，保持失败输出，详见 [数据说明](../crates/cpu6502/tests/data/README.md)。RDY/SO、半周期输入、物理 RESET 同步／保持／释放及等待预算已实现；独立的 419 组 RESET 参考观察全部通过实际 CPU 对照，另有 37 组改变 PC／RAM／寄存器／向量的独立交叉验证。

**验收**：中断测试程序及每项边界序列通过，结果包含寄存器／栈／向量、周期数量和总线事件；采样规则、修订假设及尚未覆盖的硬件窗口有可核对清单。上述承诺的目标范围仍有已知差异时不得勾选完成。

### M2.5：调试、回归与工程收尾（本地已验收）

## M2 收尾记录与后续里程碑

物理 RESET 先建立独立 revD 参考基线，随后接入 `set_reset_line` 和真实执行器对照。419 组覆盖 NOP、读写、RMW、栈和 BRK/IRQ/NMI 入口的断言／保持／释放，以及短脉冲、再次断言、RDY 和中断重叠。普通离线测试现在逐周期执行全部观察，而非只检查夹具；范围见 [数据说明](../crates/cpu6502/tests/data/README.md#物理-reset-对照)。

执行器已分离普通栈地址与 SP 提交，保留正常总线阶段的数据／ALU 中间值，并区分存储 PC 与外部地址锁存。RESET 同步期间继续表达已启动的传送、被抑制写周期读到的数据和短脉冲暂态；没有将释放映射为宿主 `begin_reset`，也没有固定地址或测试程序特判。既有七周期宿主契约保留，见 [架构](architecture.md#物理-reset)。

M2.2～M2.4 的完整固定范围已重新验证：官方单步寄存器／内存、周期和总线，Klaus 功能／十进制／明确延迟配置的中断程序，以及 246＋419 组 CPU 引脚对照。原模型重放另行执行，不能替代 CPU 验收。没有由此宣称所有官方指令×引脚相位的笛卡尔积均已穷举。

M3 Apple I 文本系统：M3.1～M3.4 的目标项已逐条落地并测试，包括此前遗留的 ROM 资源冲突、40×24 屏幕与滚动模型、键盘／显示握手边界、批次一致性、物理 RESET（`set_reset_line`）、CLI 的 raw-mode 单键生命周期（RESET／CLEAR SCREEN／重建机器／暂停／退出／外部信号恢复）以及 2026-09-11 的功能级修复（PIA 寄存器选择与消费语义、跨 RESET 的按键保留、CLEAR SCREEN、严格 session 预算、ROM 身份校验、有界 trace、真实终端 40×24 网格）；仍有 DRAM 刷新时钟与固定显示延时的明确近似、配置资料未逐页核对原始手册等已知缺口（见 M3.4），**M3 整体验收因此仍未勾选**。RDY 保持验收对当前固定配置不适用，不作为 M3 阻塞项。M4／M5 仍为未开始的计划，不因这些进展自动启动 Apple II 或浏览器开发。

## 数据与实现约束

- 沿用已核对的 [SingleStepTests NMOS `6502/v1`](https://github.com/SingleStepTests/65x02/tree/2f6980a2d95757486c7bee24355c360e40e2a224/6502) 与 [Klaus/Bruce Clark 测试](https://github.com/Klaus2m5/6502_65C02_functional_tests/tree/7954e2dbb49c469ea286070bf46cdd71aeb29e4b) 固定提交；原始格式、配置开关以相应来源为准。升级数据版本另做可审查变更，记录文件清单、哈希、选择规则、逐文件许可证及使用方式。[十进制配置与结束条件](https://github.com/Klaus2m5/6502_65C02_functional_tests/blob/7954e2dbb49c469ea286070bf46cdd71aeb29e4b/6502_decimal_test.a65) 不能沿用默认关闭的 N/V/Z 检查。
- 小型固定夹具随仓库提供；完整数据通过显式准备命令下载到缓存并校验，测试执行本身不联网。下载和汇编属于宿主工具；JSON 解析等依赖只放测试／宿主侧，CPU 核心继续保持无第三方运行依赖。
- CPU 独立性、结构化错误和有限执行预算继续遵守 [架构契约](architecture.md)，实现使用安全 Rust、禁止 `unsafe`。M0～M2 仅有 CPU 与 CLI 两个 crate；M3／M4 只在真实实现需要时增加机器模块或 crate，不预建空包、插件系统或通用多架构框架。
- 本阶段目标仍是经典 NMOS 官方指令。非官方 opcode 作为 CPU 后续候选单独定范围；暂维持明确错误，不混入 65C02／NES 行为或批量当作 NOP。项目许可证仍待所有者确认，不因接入测试更改项目许可证，不引入 Apple ROM。

## 机器阶段的共同规则

- M3 已进入实现；下列待办只有在全部目标实际实现并验证后才能勾选。已落地的部分能力另记进展，不以基础演示或历史测试通过代替整阶段验收；M4／M5 不预建机器、磁盘或前端工程。
- 机器模块拥有内存映射和设备状态；CPU 继续只通过 Bus 访问。宿主负责文件、终端、墙钟节流及停止条件，不把文件 I/O、休眠或展示放进 CPU／机器执行逻辑。
- 用模拟周期推进 CPU 和设备，必要时明确半周期事件位置。设备握手、视频和音频不能依赖终端刷新次数或宿主运行速度；不同推进批次必须可重放相同输入序列。
- 原始手册、原理图和目标固件在各阶段入口核对并记录链接、章节、修订与采用的假设。实现存在不代表对应硬件依据已核对完成；尚未闭合的配置与资源项仍须明确保留。
- 不提交 Apple ROM、商业软件或来源不明镜像。合法资源由宿主加载，记录版本、大小、哈希和使用权限；公开可下载不等于有权再分发。资源缺失时可继续原创程序验证，但不能将相应系统联调标为通过。
- 普通回归自包含、离线可运行；外部固件／软件联调单独显式执行，缺数据、哈希不符、零匹配或超限必须明确失败。目标程序若需要未支持 opcode，另行决定是否扩展 CPU 范围，不能静默 NOP 或修改原程序绕过失败。

### M3.1：配置依据、资源前提与机器总线（功能模型已验证，硬件差异未关闭）

**前提**：M2 本地目标范围已验收。先核对 Apple I 原始操作手册、原理图及所用 I/O 器件资料，不凭其他模拟器的地址表直接实现。

- [x] 固定一套初始配置，列出 RAM／ROM 区间、地址译码与镜像、I/O 寄存器、未映射访问、ROM 写入行为、时钟和复位／清屏输入。明确哪些是硬件资料结论，哪些是可重复模拟所需的初值约定；不提前支持任意 RAM／外设组合。
- [x] 确定目标监控程序及获取／加载条件，记录文件布局、入口、向量、版本和哈希；同时准备原创的小型总线验证程序。不能等机器实现完才核对固件权限或型号。
- [x] 实现机器 Bus 的 RAM、只读 ROM 与真实地址译码；I/O 按随后阶段逐项实现，不先用恒定“就绪”寄存器冒充设备。范围外的硬件行为与未实现的目标项必须区分，不能用未映射规则隐藏缺失实现。

2. D8/D9 垂直计数器 preset 的十进制值与滚动时的帧长变化未逐位复现（H18）；B3 的 3.5 µs 按标称值量化到整主时钟周期，不是 74123 的容差认证。
3. 视频只到字符格：2513 字模、D1 像素移位寄存器与复合视频未建模；DRAM 单元电荷保持与真实上电随机态未建模。

这些是范围明确、可独立关闭的剩余项，不是模糊的“以后再看”；补齐后才应勾选 **M3 整体验收**。历史验证记录中曾经出现的“M3 整体验收完成”结论范围过宽，此前已撤回；本轮关闭了当时点名的资源冲突与生命周期缺口，但没有据此重新宣称整体验收，以免重复同一个错误。最新记录未报告远程 CI 通过或推送／发布状态。


## M4：原版 Apple II（规划，未开始）

- [ ] **M4 整体验收**。文本、图形、声音与磁盘四个子阶段分别验证，再汇总为固定配置的整机结果；文本启动或只读磁盘引导通过均不能单独代表 M4 完成。

默认在 M3 整体验收后启动。复用 CPU 及已经验证的周期推进／诊断逻辑，不沿用 Apple I 的内存映射、键盘或显示假设。首个目标是原版 Apple II 的一套 NTSC 配置；主板修订、RAM 容量、原版固件和字符资源在 M4.1 依据资料固定。Disk II 作为 M4.4 的明确扩展配置另列，不当作所有原版主板共有的内置设备。

不默认混入 Apple II Plus／IIe／IIc 固件、65C02、80 列、双高分辨率、扩展内存、其他存储卡或游戏控制器。未列出的机型／外设另行定范围；图形颜色与音频重建需记录所选数字模型，不宣称完整模拟模拟电路。

### M4.1：原版配置、键盘与文本系统

**前提**：复用经过验证的运行循环；先核对原版 Apple II 参考手册、原理图和目标固件，不把后续机型行为当作默认。

- [ ] 固定基础机器配置与资源清单，列明 RAM／ROM／字符资源、插槽占用、地址镜像、未映射／浮动总线行为、复位和视频时钟。空插槽与未实现设备分别记录；启动监控程序所需的合法资源是本阶段验收前提。
- [ ] 实现内存译码和相关软件开关，区分读取、写入及其副作用。键盘数据与清除选通遵循实际地址译码；CPU dummy read、RMW 和重复访问不能被宿主合并或过滤。
- [ ] 实现文本页的地址排列、页面选择、字符与反显／闪烁等所选配置行为。闪烁和显示进度由模拟时间驱动，不能读取宿主墙钟；若开发时用原创字形代替字符资源，必须标明，不能据此通过原字形验收。
- [ ] 接入现有宿主的加载、输入、暂停和复位流程，保留 Apple I 独立配置。只有实际共享的逻辑才抽取复用，不为两台机器预建插件体系或任意外设装配框架。

**验收**：原创程序覆盖内存区间、键盘选通、软件开关、非连续文本地址、页切换与字符属性；独立预期检查文本屏幕和设备副作用。合法目标固件实际启动并完成内存操作和原创程序执行，CLI 可交互，复位可恢复所记录状态；Apple I 与 CPU 回归保持通过。

### M4.2：低分辨率、高分辨率与视频时序

**前提**：M4.1 的内存、软件开关、文本与模拟时钟已通过验收。本阶段不等待磁盘或浏览器。

- [ ] 按固定原版配置实现低分辨率、高分辨率、文本混合和页面选择，覆盖各自地址排列及开关的读写语义；不以连续 framebuffer 的布局替代 Apple II 显存译码。
- [ ] 按资料固定扫描与可见区时序，检查帧内显存写入、页／模式切换及混合区交界的可见结果；不能把执行结束时一次性读取全部显存称为逐扫描时序正确。
- [ ] 先验证像素位置与高分辨率单色结果，再验证选定 NTSC 彩色重建规则；用独立推导的位图／条纹／边界图案区分地址错误、位序错误、邻接像素及颜色相位错误。不能由被测渲染器反向生成预期图片。
- [ ] 提供宿主侧可查看的图像输出，实际检查文字／图形、两页切换与混合画面。渲染使用明确的机器输出／无副作用显示数据，不能为截图额外执行设备 Bus 读取。

**验收**：所选配置的各显示模式、页切换、混合区与帧内变化都有固定程序及独立图像预期；实际导出并查看图像。报告像素／扫描时序与颜色模型各自的验证范围，不以单张“看起来正确”的截图代替对照，也不把数字颜色近似宣传为模拟视频电气认证。

### M4.3：扬声器与可验证音频

**前提**：M4.1 的软件开关和周期推进通过；与 M4.2 没有必须等待的实现依赖。

- [ ] 按资料实现扬声器开关的读写及地址别名，记录准确的模拟周期翻转事件。包含 CPU 重复访问和 dummy access 的效果，trace 不能产生额外翻转。
- [ ] 由模拟时间生成固定采样约定的音频，保留跨批次的采样余量；宿主墙钟只负责播放节流。暂停、继续、变速展示及不同执行批次不能改变同一事件序列对应的离线波形。
- [ ] 由宿主导出可播放的音频并实际试听；明确幅度、采样率和采用的重建假设。不把音频设备、文件写入或宿主回调放入 CPU，不为基本声音引入通用音频框架。

**验收**：原创程序产生的单次翻转、方波和静音具有独立的边沿时刻、频率与持续时间预期；不同批次下输出一致，无意外额外边沿。文件可实际播放，数值对照与试听结果分别记录；不会仅以“听得到声音”判定时序通过。

### M4.4：Disk II、磁盘读写与启动

**前提**：M4.1 通过，并取得合法、版本明确的磁盘控制器固件和测试介质。图形、声音、浏览器不是磁盘实现的硬依赖。

- [ ] 首轮固定一块控制卡和一台驱动器的配置，记录槽位、控制器修订与固件、轨道／扇区编码及一种明确的镜像布局。核对 13／16 扇区和不同扇区顺序等差异，选择一个有资料与验收介质支持的组合，不按文件后缀猜测格式；原版主板兼容性单独核对。
- [ ] 实现控制器开关、磁头步进、电机、驱动器选择、数据锁存及读写模式，旋转与数据可见性按模拟时间推进。CPU 必须通过真实 I/O 访问控制器，不能拦截 ROM 入口或把磁盘扇区直接复制到约定 RAM 冒充启动。
- [ ] 先以只读路径完成所选镜像的引导和跨轨读取，检查扇区内容、必要控制器访问与预算；无介质、错误镜像、越界参数和不受支持编码分别有明确处理。合法等待可由宿主停止，不能变成无限执行或假成功。
- [ ] 随后实现所选格式内的写入、写保护与持久化验证。默认不覆盖用户原镜像，写入可保留在工作副本并由宿主显式导出；导出失败不得部分覆盖原文件。镜像不能表示的写入结果必须明确报告，不静默丢弃后宣称保存成功。
- [ ] 固定一套许可明确、与目标配置匹配的磁盘引导／读写场景；记录成功条件、文件哈希和全部运行参数。测试介质可用原创内容生成，预期由已知内容和格式规则独立确定；不默认覆盖保护盘、任意位流格式、多驱动器或其他控制卡。

**验收**：在有限总预算内经真实控制器路径启动目标磁盘程序，读出并核对指定数据；完成写入、导出后重新加载和再次读取对照。写保护有效，用户原镜像保持不变；不支持的布局与失败导出不伪装成功。只读引导是阶段内的中间验收，不足以勾选整个磁盘子阶段。

### M4 整机回归与交付条件

- M4.1～M4.4 各自保留原创离线回归、真实输出证据和有预算的外部联调入口；完整机器验证使用同一份明确配置，不能把互不兼容的 ROM／主板／控制器组合的局部结果拼成一次整机通过。
- 复验键盘、屏幕、音频与磁盘同时运行时的周期推进、暂停恢复及复位；改变宿主批次后结果一致，I/O 副作用与日志互不干扰。保留最后有限 trace、显示／音频输出和介质标识供定位。
- 普通 CPU／Apple I／Apple II／CLI 回归全部通过；CPU 若有行为改动，再运行完整的受影响外部一致性范围。架构、资源清单、支持矩阵、实际运行方法及未覆盖行为同步记录；缺固件或介质的联调不得静默跳过后勾选 M4。

## 阶段依赖与实现顺序

| 阶段 | 前提 | 完成不等于 |
| --- | --- | --- |
| M3.1 | M2 验收；资料与配置明确 | Apple I I/O 或系统交互完成 |
| M3.2 | M3.1 | CLI 或目标监控程序已联调 |
| M3.3 | M3.2 | 整个 Apple I 已验收 |
| M3.4 | M3.1～M3.3；合法目标资源 | 其他机器配置全部兼容 |
| M4.1 | 默认 M3 整体验收后启动；固定原版配置 | 图形、声音或磁盘完成 |

默认按 Apple I → Apple II 文本 → 图形 → 声音 → 磁盘交付；M4 的图形、声音和磁盘只有共同前提，并非彼此的硬依赖。不为可能的并行实现提前增加共享框架。

M5 不作为 M3／M4 核心验收前提：文本先用 CLI，图形／声音有实际图像／音频文件作为输出证据。若后续明确需要交互式浏览器宿主，可另行安排，不必等待磁盘完成；本轮不启动该工作，也不把 Wasm 目标编译当作浏览器验证。
