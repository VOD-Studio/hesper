# 程序 1：打印一行字符串（HELLO, APPLE 1!）

概念：字符表遍历 + 子程序调用（`JSR`/`RTS`）+ Woz Monitor 的 `ECHO` 子程序 `$FFEF`。这是最基础的"跑一段自己的机器码"示例。

准备工作（获取 ROM、启动 CLI、到达 `\` 提示符）见 [`examples.md`](examples.md#2-cli-快速启动)。以下命令行均已在 Hesper 上实测通过（`cargo test -p hesper --test apple1` 覆盖同一路径；本文档的具体字节序列额外用 `cargo run -p hesper -- apple1` 手工验证过）。

## 汇编列表

程序放在 `$0300`，字符串数据放在 `$0330`（避开 Woz Monitor 自己使用的 `$0200‑$027F` 输入缓冲区）。字符串以 `$00` 结尾。

| 地址 | 字节 | 指令 | 说明 |
| --- | --- | --- | --- |
| `0300` | `A2 00` | `LDX #$00` | X 作为字符串下标 |
| `0302` | `BD 30 03` | `LDA $0330,X` | 取第 X 个字符 |
| `0305` | `F0 07` | `BEQ $030E` | 遇到 `$00` 结尾就跳去自旋 |
| `0307` | `20 EF FF` | `JSR $FFEF` | 调用 Woz Monitor 的 `ECHO`：打印 A 中的字符 |
| `030A` | `E8` | `INX` | 下一个字符 |
| `030B` | `4C 02 03` | `JMP $0302` | 回到取字符 |
| `030E` | `4C 0E 03` | `JMP $030E` | 打印完毕，原地自旋 |
| `0330` | `48 45 4C 4C 4F 2C 20 41 50 50 4C 45 20 31 21 0D 00` | `.BYTE "HELLO, APPLE 1!",$0D,$00` | 字符串数据，`$0D`=CR，`$00`=结尾标记 |

`$FFEF` 是 ROM 里的 `ECHO` 子程序：等显示口空闲（轮询 `$D012` 第 7 位）再把 A 写出去，然后 `RTS`。调用方不需要自己处理忙等待。

## 输入步骤

在 `\` 提示符后逐行输入(每行按 Enter 结束)：

```
300: A2 00 BD 30 03 F0 07 20
308: EF FF E8 4C 02 03 4C 0E
310: 03
330: 48 45 4C 4C 4F 2C 20 41
338: 50 50 4C 45 20 31 21 0D
340: 00
```

## 运行

```
300R
```

## 实测输出

```
\
300: A2 00 BD 30 03 F0 07 20

0300: 00
308: EF FF E8 4C 02 03 4C 0E

0308: 00
310: 03

0310: 00
330: 48 45 4C 4C 4F 2C 20 41

0330: 00
338: 50 50 4C 45 20 31 21 0D

0338: 00
340: 00

0340: 00
300R

0300: A2HELLO, APPLE 1!
```

`0300: A2` 是 `300R` 前 Woz Monitor 对当前地址的例行回显（examine 上一次 deposit 的字节，不是我们程序的输出）；紧跟着的 `HELLO, APPLE 1!` 才是程序通过 `JSR $FFEF` 打印的内容。

## 说明：跑完之后回不去 monitor

`$030E` 的自旋是死循环，CPU 不会再去轮询键盘（`$D011`）。这之后再敲任何命令都不会被处理——键盘数据会进 PIA 队列，但没有代码去读它，Woz Monitor 也就不会回显或执行。已实测确认：跑完这个程序后再输入 `FF00.FF0F`，输出里完全没有它的痕迹。要继续用 monitor，需要退出并重新启动 `cargo run -p hesper -- apple1 --rom <ROM>`（真实 Apple 1 上则是按物理 RESET）。
