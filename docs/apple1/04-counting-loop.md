# 程序 4：无限循环打印 0123456789

概念：不依赖字符表，直接用 ASCII 码的连续性（`'0'..'9'` 是 `$30..$39`）生成字符；一个真正不会停的无限循环。是根目录 `cargo run -p hesper`（把 `0..9` 写到 `$0200..$0209` 就停）在 Apple 1 上的对应版本——区别是这里没有停止条件，会一直打印，且是打到真实显示口而不是内存。

准备工作见 [`examples.md`](examples.md#2-cli-快速启动)。

## 汇编列表

| 地址 | 字节 | 指令 | 说明 |
| --- | --- | --- | --- |
| `0300` | `A2 30` | `LDX #$30` | X＝`'0'` |
| `0302` | `8A` | `TXA` | **digloop**：把当前数字放进 A |
| `0303` | `20 EF FF` | `JSR $FFEF` | 打印这一位 |
| `0306` | `E8` | `INX` | 下一个数字 |
| `0307` | `E0 3A` | `CPX #$3A` | 是否已经过了 `'9'`（`$3A`＝`':'`） |
| `0309` | `D0 F7` | `BNE $0302` | 没到就回 digloop |
| `030B` | `A9 0D` | `LDA #$0D` | 十个数字打完，CR |
| `030D` | `20 EF FF` | `JSR $FFEF` | 打印 CR，换行 |
| `0310` | `4C 00 03` | `JMP $0300` | 回到最外层，重新从 `'0'` 开始 |

## 输入步骤

```
300: A2 30 8A 20 EF FF E8 E0
308: 3A D0 F7 A9 0D 20 EF FF
310: 4C 00 03
```

## 运行

```
300R
```

## 实测输出（用 `--max-cycles 2000000` 截断)

```
300R

0300: A20123456789
0123456789
0123456789
…（重复）
012345
[max cycles reached: 2004000]
```

程序本身没有停止条件，会一直打印 `0123456789` 直到你手动中断。实测中用 `--max-cycles` 在中途截断，最后一行被砍在半截（`012345`），这正是"预算用完就停"的预期行为，不是 bug。

## 说明：这个程序连"看起来 idle"的机会都没有

程序 1/3 跑完后 CLI 会误以为"空闲"（因为死循环不产生输出，凑够 3 个空批次就被当成"在等键盘"），但程序 2 是真的在等键盘。这个程序则是另一种极端：它**持续不断**产生输出，CLI 的空闲判定永远不会触发，交互式 CLI 里会一直刷屏，只能用 `--max-cycles`（脚本场景）或 `Ctrl+C`（交互场景）打断；它也完全不读键盘，中途打字不会有任何效果。真实 Apple 1 上同理，只能按物理 RESET。
