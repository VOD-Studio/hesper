## 3. 依赖与技术选择

采用 Ratatui 0.30.2，保留现有 Crossterm 0.29。官方说明两者默认兼容。Ratatui 使用宿主驱动的即时绘制，适合现有周期循环；不因使用 Ratatui 引入 Tokio 或独立 UI 线程。[后端兼容说明](https://ratatui.rs/concepts/backends/)、[渲染模型](https://ratatui.rs/concepts/rendering/)、[发布记录](https://github.com/ratatui/ratatui/releases)

依赖策略：

- `ratatui = "0.30.2"`：布局、列表、文本、边框、缓冲区和测试后端。
- `crossterm = "0.29.0"`：沿用键盘、窗口尺寸、raw mode、备用屏幕、粘贴等能力。
- 配置序列化采用 `serde` + `toml`；配置目录采用 `directories::ProjectDirs::from("", "", "hesper")`。执行时选择兼容的稳定版本并更新 Cargo.lock，不使用 Git 主干依赖。[TOML 官方 API](https://docs.rs/toml/latest/toml/)、[ProjectDirs 官方 API](https://docs.rs/directories/latest/directories/struct.ProjectDirs.html)
- 配置依赖仅添加到 CLI；CPU crate 保持无运行时依赖。
- 优先使用 Ratatui 的布局和文字宽度能力。确有无法覆盖的字符处理需求时再添加小型依赖，并说明用途。
- 不同时引入另一套 TUI 框架、通用状态库、动画库、主题框架或 CLI 解析框架。
- 不同时启用两套终端初始化和 panic hook；Ratatui 后端复用统一 guard 管理的终端。
- 检查 `cargo tree -p hesper`，确保实际使用同一 Crossterm 版本。锁文件稳定后优先使用 `--locked`。

## 4. 入口与非交互兼容契约

### 4.1 参数行为

| 调用 | 行为 |
| --- | --- |
| `hesper`，stdin/stdout 均为终端 | 启动中心；默认选 Apple-1，之后可记住上次选择，但始终先显示选择界面 |
| `hesper`，任一输入/输出不是终端 | 保持当前计数演示的纯文本输出和退出行为 |
| `hesper tui` | 显式启动中心；stdin/stdout 任一不是终端，或 `TERM=dumb`，打印清晰错误并失败 |
| `hesper demo [OPTIONS]` | 无论是否 TTY，均执行现有计数演示；支持原演示参数 |
| `hesper --trace` 等旧顶层演示参数 | 兼容为 demo 参数，不进入 TUI |
| `hesper apple1 [OPTIONS]`，stdin/stdout 均为终端 | 直接进入 Apple-1 TUI；缺启动资源时进入配置页 |
| `hesper apple1 --rom <path> ...`，stdin 非终端 | 继续现有按行/批次运行路径；EOF 和预算退出保持原义 |
| `hesper apple1 --rom <path> ...`，stdin 为终端、stdout 非终端 | 保留逐键的文本流宿主；不绘制 TUI、不进入备用屏幕、不向 stdout 写界面控制序列 |
| `hesper --help` / `demo --help` / `apple1 --help` / `tui --help` | 直接输出说明；不初始化终端、不执行机器、不读取用户配置 |

补充规则：

- 非 TUI 的 Apple-1 路径继续要求显式 `--rom`，不隐式使用个人配置，保持脚本可复现。
- TUI 中显式传入的 ROM 或程序路径错误时报告该错误，不静默换用已保存的文件。
- `TERM=dumb` 时无参数入口回退为 demo；显式 `apple1` 走普通按行文本宿主，不启用 raw mode 和颜色；资源必须显式指定。
- 纯文本 demo 不读写 TUI 配置，其 stdout/stderr 不受配置损坏、主题等影响。
- 不需要新增 `--headless`、通用模式矩阵或新的子命令框架；上述入口已覆盖本轮要求。
- 保留 `--max-steps`、`--max-cycles`、`--trace`、`--bus-trace`、`--trace-limit`、`--cycles-per-char`、`--program` 的既有类型、范围和错误约束。
- 当前 Apple-1 正常退出、EOF、预算停止均为成功停止；非法参数、ROM/程序错误、CPU 错误仍失败。不要在 UI 重构中无意改变退出码。
- 直接 `apple1 --max-cycles N` 达到预算时自动结束进程，输出有界诊断，不留在等待输入的弹窗中。
- 直接 Apple-1 TUI 发生 CPU 错误时允许先展示错误屏幕，但不能继续自由运行；若退出且错误未恢复，返回失败。非交互路径仍立即按既有错误行为结束。

## 5. 页面、导航与会话生命周期

### 5.1 页面范围

首版包含：启动中心、Apple-1 运行页、6502 演示结果页、启动配置、模拟器信息、显示设置、帮助，以及必要的确认/错误弹窗。

主菜单为「模拟器」「会话」「显示」「帮助」。F10 在所有 TUI 页面激活顶栏菜单，左右键选择主菜单，上下键选择菜单项，Enter 执行，Esc 关闭并回到原焦点；F2 仍可直接打开会话菜单。列表使用上下键移动、Enter 执行；Tab/Shift+Tab 在表单或按钮组中切换焦点。鼠标作为可选增强，默认关闭，不影响完整键盘流程。

启动中心左侧仅显示实际已实现的 Apple-1 和“6502 内置演示”。不要加入可点击但没有实现的 Apple II 条目。以后实际接入第二种机器时再扩展静态条目和分支。

### 5.2 启动中心详情

Apple-1 详情包含：

- 名称、简短介绍、当前实现范围。
- MOS 6502 / NMOS、40×24 字符屏幕、4 KiB RAM、256 B Woz Monitor ROM。
- ROM 状态：未配置、待校验、已校验、不可用。状态必须来自真实检查。
- 当前选定 ROM 路径、可选程序路径，以及启动操作。
- 按钮：「启动/继续会话」「配置」「模拟器信息」。

默认布局为左侧选择、右侧详情，下方始终显示当前快捷键。没有活跃会话时启动动作创建会话；已经有 Apple-1 会话时默认操作为继续，不隐式重建。

模拟器信息同时说明固定内存映射与已知近似。内容以当前 `crates/apple1/src/lib.rs`、`docs/roadmap.md` 及有效硬件证据为准，不能把硬件理论规格写成当前实现已完整通过的兼容性声明。

### 5.3 会话保留

- 一个 Hesper 进程首版最多保留一个 Apple-1 会话。
- 从运行页返回启动中心：保留原机器对象、CPU 执行中间态、RAM、设备、屏幕、光标、输入队列、预算、trace 与启动资源；停止自由运行。
- 点击继续：返回原机器对象。返回中心前主动暂停的会话继续保持暂停；原来运行中的会话恢复运行。
- 开启菜单/帮助/设置也只是临时阻止自由运行，不修改用户主动暂停的意图。
- 6502 演示可以在 Apple-1 会话保留期间运行，Apple-1 继续暂停。演示只调用现有有界 runner，不成为第二个常驻机器线程。
- 修改 ROM、程序或字符时序属于“下次启动配置”。应用到现有会话时必须走明确的新建/重建操作，不能热换机器资源。
- 用户取消替换时，现有会话与原启动配置仍可继续。
- 退出 Hesper 后没有会话恢复能力；UI 用“本次进程内保留”，不使用“存档”措辞。

### 5.4 重建、退出与错误

“重新上电”明确表示使用本次会话已经校验并读入的 ROM/初始程序字节重建。只在重新选择资源并新建时读取新文件。

重建当前会话保留 session 累计周期、总预算和 trace，清零的是新机器自身的计数。不能以重建规避 `--max-cycles`。已有内存状态将丢弃，因此弹窗确认，默认选取消。RESET 和清屏直接执行，不弹确认框。

有活跃机器时，TUI 中 Ctrl+C/Ctrl+D 或菜单退出打开一次退出确认；确认后恢复终端并退出。没有活跃机器时直接退出。外部 SIGINT/SIGTERM/SIGHUP/SIGQUIT 继续按现有信号路径及时退出，不等待确认。文本流路径保留既有 Ctrl+C/Ctrl+D 直接退出语义。

CPU 错误把会话置为 Faulted，保留最后屏幕、失败位置和有界 trace；自由运行停下，用户可查看、尝试 RESET、重新上电或返回中心。不能把普通“继续”当作错误恢复。RESET/重新上电只有成功完成后才清除可恢复的故障状态。

## 6. ROM、程序与配置持久化

### 6.1 资源配置流程

`选中 Apple-1 → 配置 ROM → 校验 → 保存路径 → 启动`。

- 配置表单提供 ROM 路径输入、目录浏览、可选程序路径，以及“校验并保存”“启动”“取消”。
- 路径输入支持空格和中文；粘贴当作文本，不执行 shell 展开或命令替换。
- 浏览器支持上一级、目录进入、文件选择和错误提示；文件名按显示宽度截断，详情显示完整路径。
- 目录结果保持有界，建议最多显示 512 条，超限时提示输入更具体路径；不递归遍历文件系统。表单始终允许直接输入目标路径。
- ROM 沿用当前 256 字节和固定 SHA-256 身份校验，不新增跳过校验选项。
- 程序沿用当前 raw bytes、装入 `$0000`、最多 4 KiB 的规则；不新增加载地址或自动执行语义。
- 验证完成前不修改现有机器；启动前所有资源整体通过后才构造新机器。
- 交互路径可预填已保存 ROM。没有保存路径时，可提示当前目录下存在的 `.cache/apple1/wozmon.bin` 候选，但必须实际校验；不扫描用户目录、不自动下载。
- 显式路径优先，其次已保存路径；候选路径只用于未配置时的引导。上层路径失效时显示原因，不悄悄降级。
- 每次新建会话重新读文件并校验；仅回到已有会话时不重新读 ROM。
- 校验失败保留表单输入，并分别说明文件不可读、长度不符、哈希不符或程序过大。

### 6.2 配置文件

使用上述 ProjectDirs 返回的 `config_dir()/config.toml`，配置页展示实际路径。文件格式示例：

```toml
schema_version = 1
last_selected = "apple1"

[ui]
screen_color = "green" # green / amber / white
sidebar = true
border = "rounded" # rounded / ascii
color_mode = "auto" # auto / truecolor / ansi256 / mono
mouse = false

[apple1]
rom_path = "/absolute/path/to/wozmon.bin"
cycles_per_char = 1000
```

- 没有配置时使用默认值，不作为错误。
- 不保存 RAM、寄存器、输入队列、trace、ROM 内容、运行预算或自动启动指令。
- 可选程序选择首版只保留在本次进程中，避免下次无意加载旧文件。
- 已成功确认的路径保存为绝对路径；不能将非 UTF-8 路径有损转换后写入另一个路径。无法持久化时保留本次有效选择并解释限制。
- 新字段提供默认值；不支持的 schema_version、非法枚举值和损坏语法给出可理解的诊断。
- 损坏配置不自动覆盖：允许用户本次使用默认值；覆盖原文件需通过明确“保存设置”操作。
- 写入采用同目录临时文件后替换，失败保留原文件；只在设置变化且用户保存/确认时写入，不每帧保存。
- 保存失败不退出模拟器、不谎称已保存；允许仅本次使用，保留重试入口。
- 纯配置函数接收路径/配置值参数。测试使用独立临时目录，不通过修改全局 HOME 或不安全的进程环境变量隔离测试。
- 同一进程在启动配置和显示设置中共用一份配置状态，不能互相覆盖已经修改的字段。

## 7. 运行页和视觉规格

### 7.1 全尺寸布局

以下为区域关系，屏幕行数为示意省略；实现必须完整绘制 24 行：

```text
HESPER  经典计算机模拟器                               Apple-1
模拟器    会话    显示    帮助

       ┌ APPLE-1 DISPLAY · 40×24 ┐          机器状态
       │                        │          PC  $....
       │  40 列真实屏幕内容      │          A   $..
       │  完整保留 24 行         │          X   $..
       │                        │          ...
       └────────────────────────┘          会话累计周期

运行中     [RESET] 已完成 · RAM / 屏幕保留          输入 → Apple-1
F1 帮助   F2 菜单   Ctrl+P 暂停   Ctrl+R RESET   Ctrl+L 清屏
```

| 区域 | 必须展示 / 实现 |
| --- | --- |
| 顶部 | Hesper、当前页面/机器、主菜单；版本使用实际构建版本 |
| 屏幕 | 40×24 固定字符网格和正确光标偏移；边框在网格外 |
| 状态侧栏 | 实际 PC/A/X/Y/SP/P、会话累计周期、输入待处理与否、当前 cycles_per_char |
| 状态栏 | 持续运行状态、独立短时通知、当前输入目标 |
| 快捷键栏 | 当前可用命令；窄屏优先保留菜单、帮助、暂停与退出 |

默认侧栏只展示现有公开观察接口能提供的状态。键盘目前只有 `has_pending()`，因此显示“有/无待处理输入”，不要为数字计数扩展机器 API。寄存器按采样时的真实值显示，不臆造“已完成指令状态”。

会话累计周期从 Session 读取，不能误用重建后归零的 `Apple1::total_cycles()`。若同时显示机器累计周期，必须分别命名。

实测速率为加分项而非首版阻塞项。若实现，必须基于周期增量和对应的活动墙钟间隔，注明“实测执行速率”；不显示未实现的“原速 1×/1 MHz”。

### 7.2 字符屏幕

- 只从 `Display::screen()` 和 `cursor()` 投影；不用输出流另建终端状态模型。
- 直接映射固定位置，不启用文本自动 wrap，不居中每一行，不拉伸网格。
- 每个机器单元固定占一个终端 cell；保持现有安全投影：可打印 ASCII 显示自身，其余控制字节显示空白。
- 禁止把机器输出中的 ESC/控制字节交给宿主终端解释。
- 光标位置 = 网格原点 + 机器 `(column,row)`；菜单/表单获得焦点时隐藏机器光标，表单使用自己的编辑光标。
- 只使用一套光标方案，不同时绘制块光标和显示终端光标；首版优先使用可定位的终端光标。
- 渲染和观察不推进 CPU，不读取可能产生副作用的总线地址。
- 仍需及时 drain 已完成字符队列，即使 TUI 只从网格绘制；否则 `Display` 的输出队列会持续增长。
- 调整窗口、切换主题或隐藏侧栏后，整帧正确覆盖旧区域，不能留下字符和颜色残影。

### 7.3 配色和可访问性

建议初始颜色 token（真实颜色不足时映射 ANSI 色）：

| Token | Truecolor 初值 | 用途 |
| --- | --- | --- |
| background | `#11151D` | 外壳背景 |
| panel | `#191F2A` | 菜单、状态区域 |
| border | `#374252` | 分隔线与边框 |
| foreground | `#E5EAF2` | 主文字 |
| muted | `#A2AFBF` | 次要说明，仍需可读 |
| accent | `#8CAFFF` | 选中项、快捷键 |
| screen background | `#0C1511` | 机器屏幕 |
| green / amber / white | `#9BDFA4` / `#F0CB8A` / `#D8E3D8` | 屏幕文字 |
| notice | `#F1C47E` | 操作反馈 |

- 深色外壳固定为首版主题，显示设置只提供上述已有选项，不扩展主题市场。
- 状态使用文字和符号共同表达，单色模式仍可区分运行、暂停、故障及焦点。
- `NO_COLOR` 在 auto 模式下启用单色；用户在设置中的显式色彩模式可覆盖 auto。
- auto 模式根据终端能力保守选择 truecolor/ANSI，不因库支持 RGB 就认为所有终端支持。
- 圆角线框来自终端字符；ASCII 模式只用标准 ASCII 边框和提示符号。
- 不依赖 Nerd Fonts、终端图片协议、浏览器阴影、模糊或渐变才能成立。
- 中文按终端 cell 宽度布局，不使用字节数或 `.chars().count()` 当作显示宽度。
- 默认无持续扫描线、闪屏、进场动画；避免没有信息变化的反复绘制。

### 7.4 尺寸规则

建议体验尺寸为 `96×32` 及以上；只有实际空间充足时才展示状态侧栏。

紧凑模式最小支持 `44×30`：40×24 内屏 + 2×边框 + 左右各 1 cell 外边距；高度为顶栏 1、菜单 1、屏幕含边框 26、状态 1、快捷键 1。紧凑模式不再增加垂直 padding。

- 宽度不足以放侧栏时自动隐藏，即使偏好中启用了侧栏；窗口恢复时按偏好恢复。
- F3 切换用户的侧栏偏好。此切换不能改变机器屏幕尺寸。
- 低于 `44×30`，暂停自由运行并展示需要的尺寸和当前尺寸；不以裁掉机器输出作为默认操作方式。
- 小尺寸状态保留菜单/退出的可用入口；禁用 RESET、清屏、重建、机器输入等依赖正常运行画面的动作。
- 过小到帮助或确认弹窗也放不下时，使用可截断的紧凑文本提示和固定确认/取消按键，保证 Ctrl+C/Ctrl+D 能请求退出、Enter 确认、Esc 取消；不分配负尺寸、不 panic。
- 尺寸恢复只移除“空间不足”这个暂停原因，不移除用户主动暂停或菜单暂停。
- 至少测试 `120×40`、`96×32`、`80×30`、`44×30`、`80×24`、`39×23`、`1×1` 和零尺寸缓冲区。

## 8. 输入、命令和暂停状态契约

### 8.1 快捷键

| 命令 | 运行页按键 | 语义 |
| --- | --- | --- |
| 帮助 | F1 | 完整快捷键表，临时暂停 |
| 会话菜单 | F2 | 菜单：返回屏幕、暂停/继续、RESET、清屏、重新上电、返回启动中心、退出 |
| 专注屏幕 | F3 | 切换状态侧栏偏好 |
| 顶栏菜单 | F10 | 激活主菜单，可仅用键盘访问显示设置等入口 |
| 暂停/继续 | Ctrl+P | 改变用户主动暂停意图 |
| 物理 RESET | Ctrl+R | 沿用会话内真实复位流程；预算仍有效 |
| CLEAR SCREEN | Ctrl+L | 调用机器清屏；不执行 CPU 周期 |
| 重新上电 | Ctrl+N | 确认后重建；沿用同一会话预算 |
| 退出 | Ctrl+C / Ctrl+D | TUI 有会话时一次确认；流式模式直接退出 |
| 普通输入 | ASCII 可打印键 | 发给 Apple-1，字母归一化由现有键盘模型负责 |
| Enter | Enter | CR |
| 擦除键 | Backspace | `_`，不是直接修改屏幕 |
| 机器取消输入 | Esc | 发给 Woz Monitor；不能全局当作返回启动中心 |

F1/F2 在 macOS 某些键盘上需要配合 Fn。菜单也提供可选鼠标入口；首版不引入自定义快捷键配置。

输入分发顺序固定：退出/外部信号策略 → 当前最上层弹窗或表单 → 当前页面快捷键 → 机器输入。除退出外，不允许底层页面在弹窗显示期间再次消费同一按键。

例如表单中的 `q` 是路径字符；机器屏幕中的 `q` 是机器输入；菜单中的方向键只移动选择。不要同时触发两个动作。

命令声明集中维护：命令 ID、中文名称、按键、允许上下文、可用条件。菜单和 footer 使用同一份声明；不要求创建通用命令框架。

退出确认已经打开时再次 Ctrl+C/Ctrl+D 不创建第二个确认框。菜单中选择 RESET/清屏等即时动作后返回运行页；确认类操作取消后返回来源页面/菜单。顶栏菜单获得焦点也属于临时暂停原因，Esc 关闭菜单的那个事件不得继续透传给机器。

### 8.2 暂停状态

不能用一个 `paused: bool` 同时表示用户暂停、菜单、启动中心和小窗口。可以采用如下等价条件，而不需要引入状态框架：

```text
可自由推进周期 =
    有可运行会话
    且 当前页面是机器运行页
    且 用户没有主动暂停
    且 没有阻塞运行的弹窗
    且 终端尺寸足够
    且 没有故障/停止状态
```

必须覆盖：

- 运行 → 菜单 → 返回：恢复运行。
- 主动暂停 → 菜单 → 返回：保持暂停。
- 运行 → 启动中心 → 继续：恢复原会话运行。
- 主动暂停 → 启动中心 → 继续：回到暂停会话。
- 菜单中缩小窗口 → 关闭菜单：尺寸不足仍暂停。
- 用户暂停时缩小/恢复窗口：仍保持用户暂停。
- 暂停时 RESET/重新上电：显式命令执行其必要的有界周期，结束后仍保持用户暂停。

暂停状态下，屏幕获得焦点时可以接受有界的排队输入，恢复后交给机器；焦点不在屏幕时不得排入机器队列。

### 8.3 粘贴和输入上限

- 使用 bracketed paste 事件，将其中的 CRLF/LF/CR 统一成机器 CR，不能把 CRLF 当两次回车。
- 不支持的非 ASCII 字符不强制截低位；跳过并提示跳过数量，不静默变成机器字符。
- 可打印 ASCII 和规范化回车进入机器；Tab、ESC 等其他粘贴控制字节忽略并提示。物理按键 Esc 仍按表中规则发送。
- 宿主命令不能从粘贴内容触发。
- TUI 待发送队列建议最多 4,096 字节；单次粘贴及剩余容量先检查，再整体接收或拒绝，不悄悄截断后执行半条命令。
- 为避免暂停时无限增长，TUI 使用一个有界宿主队列，机器键盘已有 pending 时暂不继续灌入；没有 pending 时再通过 `type_char` 递交下一个字符。
- 普通按键按相同顺序入队；队列已满时给出明确反馈。RESET 保留宿主队列和机器已排队字符；重建清空两者。
- 该队列只属于 TUI；不改变既有 batch 输入的时序/预算行为。
- 单轮处理终端事件数量和粘贴解析工作保持有界，长输入或 resize 事件流不得饿死 CPU、绘制或退出检查。
- 主命令只处理 KeyEventKind::Press，避免 repeat/release 多次 RESET 或打开多层弹窗；普通输入先保留现有 press 语义，不顺便改变长按策略。

## 9. 状态反馈与错误呈现

持续状态与通知独立存储。持续状态从实际会话和暂停原因推导，不能用上一次通知字符串充当运行状态。

| 事件 | 通知 | 持续状态 |
| --- | --- | --- |
| RESET 完成 | `[RESET] 已完成 · RAM / 屏幕保留` | 按原运行/暂停意图 |
| 清屏 | `[CLEAR] 已清屏` | 不变 |
| 暂停 | `[PAUSED] 已暂停` | 暂停 |
| 恢复 | `[RESUMED] 已继续` | 运行 |
| 重建成功 | `[NEW MACHINE] 已重新上电` | 按原意图 |
| 配置保存失败 | `配置未保存：<简短原因>` | 会话继续；保存失败状态在配置页保留 |
| CPU 错误 | 错误详情页/弹窗 | 故障，禁止自由运行 |
| 预算耗尽 | 结束原因与实际周期 | 按入口的有限执行退出规则 |

- 操作成功通知保留 2.5 秒，使用墙钟时间；暂停期间也会过期。到期触发重绘，不能必须再按键才消失。
- 首版只保留最近一条瞬时通知，不新增无限日志面板。故障详情和保存失败不依赖瞬时通知保留。
- RESET 完成以真实 StepKind::Reset 为准；若预算在保持/释放/向量读取期间耗尽，不能显示“已完成”。
- RESET 保留屏幕不代表恢复运行后 ROM 永远不会向屏幕写字；测试应比较控制命令本身的副作用，再观察真实软件输出。
- 清屏时已有传输中的字符仍按现有设备时序完成，不能为了视觉整齐清空显示设备的在途状态。
- 终端激活期间不直接 println/eprintln trace 或错误。界面错误在界面呈现，最终诊断在恢复终端后输出。
- 纯文本 stdout 只保留该模式约定的机器/演示输出，trace 和结束诊断沿用各自现有通道。
- 文本流模式 Ctrl+L 仍作用于机器清屏，但 stdout 被重定向时不能输出终端 Clear/MoveTo 指令。

## 10. 内部结构和事件循环

以下为职责分配建议，不要求机械地创建每个文件或预先建立空模块：

```text
crates/cli/src/main.rs        参数分流与最终退出码
crates/cli/src/lib.rs         原演示和共享格式函数
crates/cli/src/apple1.rs      文本宿主/现有公共入口
crates/cli/src/apple1/        按实际规模提取 session、资源加载
crates/cli/src/terminal.rs    统一 TerminalGuard，支持完整 TUI 与 raw 文本流
crates/cli/src/config.rs      少量配置、目录定位、读取和保存
crates/cli/src/tui/mod.rs     TUI 入口与事件循环
crates/cli/src/tui/app.rs     页面、会话、焦点、弹窗和动作处理
crates/cli/src/tui/ui.rs      布局、页面、菜单、主题、footer
crates/cli/src/tui/screen.rs  40×24 屏幕 widget，若过小可合并进 ui
```

### 10.1 状态和可见性

使用少量具体类型，例如 `Page`、`Overlay`、`UiCommand`、`App`、`Apple1Session`、`LaunchConfig`、`Settings`。机器目录是静态条目，选择后直接枚举分支；不为一种机器创建 Emulator trait、注册中心或 factory。

会话与 UI 之间传递类型化结果，不能解析 `[RESET]` 字符串判断状态。通知字符串只是表现层。

尽量使用私有/`pub(crate)` 模块。保留原公共 runner 的兼容包装；不要为了测试暴露机器内部状态或增加 savestate API。integration test 通过二进制或真实公共能力验证，内部状态转移可放 CLI 模块内单元测试。

### 10.2 执行循环

首版采用单线程循环，结构为：

```text
检查外部终止信号
有界地处理可用终端事件，更新焦点/动作
若有显式控制操作，执行其有界工作并处理完成/停止
若允许自由运行，推进一个有界 CPU 批次
收集完成字符，释放显示输出队列
到期则更新通知和低频观察值
有变化且达到绘制时机时，绘制完整 Frame
按下一次事件/通知/观察/绘制期限决定 poll 超时
```

- 所有机器周期继续经过会话的唯一 `cycle` 入口，包括 boot、RESET、重建、普通输入和空闲批次。
- 不以 `machine.run_cycles()` 旁路 session 总预算，不使用 CPU host reset API 替代 Apple-1 的物理 RESET。
- 起始可复用 2,000 cycles 批次；必要时减少/切片以保证响应。改变批次长度不应改变相同绝对周期输入下的机器结果。
- 50,000 cycles boot 批次仍保持其原语义；若启动响应不足，可拆成小批次，但必须保存剩余量并持续检查信号和预算。
- 绘制上限建议 30 FPS，状态观察 5 Hz；按键、菜单和窗口变化应在下一次可绘制时刻体现，目标响应不超过 50 ms。
- 不能每执行一个模拟周期就 draw，也不能以每帧固定执行一次 CPU 指令的方式改变机器时序。
- 首版保留现有近似运行节奏，不实现原速调度。CPU 批次、输入等待和绘制频率是宿主策略，不能伪装成硬件时钟模型。
- 无状态变化的启动中心/暂停页使用有期限的事件等待，不空转；通知有到期时间时计算最近期限。
- 不通过无限忙循环提高执行速率；每轮工作有界，持续输入或无限输出时仍能及时退出。
- trace 保持有限环形缓存；默认 64，合法范围 1..4096，两种 trace 共用总上限；关闭 trace 时不格式化每周期记录。

### 10.3 终端恢复

- 一个 guard 管理信号注册、raw mode、bracketed paste、备用屏幕、光标、换行和可选鼠标捕获。
- 信号处理保持现有模式：回调只记录终止意图，由主循环正常收尾；不在 signal handler 中渲染。
- 初始化一半失败也恢复已经成功启用的能力，按逆序清理。
- 正常退出、用户取消、加载/绘制错误、CPU 错误、可捕获外部信号及 Rust panic unwind 都需要恢复终端。不可捕获终止不作恢复保证。
- `TerminalGuard` 与 Ratatui helper 的初始化/panic hook 只能有一个所有者，不出现二次 raw mode、两个事件消费者或重复备用屏幕切换。
- panic 文本应在终端恢复后可读；只包装现有 hook 一次，不在每次会话进入时安装新 hook。
- 从机器回启动中心不离开/重新进入备用屏幕；退出整个 TUI 才恢复 shell。

| ID | 场景 | 独立预期 |

## 13. 真实终端验收脚本

记录终端程序、操作系统、构建版本、尺寸、ROM 哈希及所用参数。PTY 输出字节验证生命周期，实际终端截图验证视觉；二者不可互相替代。

| ID | 操作 | 通过标准 |
| --- | --- | --- |
| P01 | 无参数启动，方向键选择，查看详情、帮助，运行 demo | 选择、菜单、footer 一致；返回流程完整 |
| P02 | 首次配置 ROM，输入带空格/中文的有效路径，再重启 | 真实校验；路径保存/读取准确；没有自动启动或自动下载 |
| P03 | 启动 Woz Monitor，输入 `0000: 41 42` 回车，再输入 `0000.0001` 回车 | 真实 ROM 经机器 I/O 写入并展示对应内存字节 |
| P04 | 输入 Woz Monitor 命令，使用 Backspace、Esc，再重新输入 | 维持原机器语义；Esc 不返回首页 |
| P05 | 输入普通字母 q、问号、空格；打开菜单/配置后输入 | 屏幕输入归机器；菜单/表单输入不会漏到机器 |
| P06 | Ctrl+P，输入若干字符，打开/关闭帮助，然后继续 | 暂停时不自由执行；关闭帮助不解除主动暂停；恢复后按序输入 |
| P07 | 写 RAM 后 Ctrl+R，观察提示，再读 RAM | `[RESET]` 在屏幕外；RAM 保留；没有以重建冒充 RESET |
| P08 | Ctrl+L，等待后继续操作 | 清的是机器显示屏，不清外壳；CPU 和 RAM 不被 reset |
| P09 | Ctrl+N，先取消再确认 | 取消完整保留；确认重建；同一会话周期累计不归零 |
| P10 | 返回中心，运行 demo，继续 Apple-1 | Apple-1 保留同一对象及内容，暂停意图符合约定 |
| P11 | 粘贴多行命令，切换窗口尺寸并产生足够输出滚动 | 换行正确；24 行硬件滚动；画面、光标和菜单无残留 |
| P12 | 切到 44×30、80×24、极小窗口再恢复 | 完整紧凑布局或明确空间不足；退出始终可达；恢复状态正确 |
| P13 | 切换屏幕颜色、ASCII、单色，测试长中文路径 | 字符对齐、可读，功能不依赖颜色和特殊字体 |
| P14 | 正常退出；运行中/暂停/菜单/boot 时发送外部信号 | 回到 shell，回显、光标、换行、鼠标和粘贴状态正常 |
| P15 | stdout 重定向后进行原交互/清屏；stdin 管道输入 | 文件/管道没有 TUI 的 ESC 控制指令；有限退出仍有效 |
| P16 | 显式小预算和 CPU 故障 | 不超预算；预算停止自动退出；故障信息真实且不能继续自由执行；非交互故障按原义失败退出 |

终端操作测试需有超时与子进程回收。已有合适 PTY 工具优先复用；确需新增测试工具时仅作为开发/测试依赖，不引入应用 runtime，也不通过 unsafe 绕过 workspace lint。

至少在用户当前 macOS 终端做实际交互和截图。Linux 有可用环境则补充，未运行的平台明确标为未验证，不阻塞其他已授权实现工作。

## 14. 最终门禁和证据要求

依次执行适当的 focused 测试和最终门禁：

```sh
cargo test --locked -p hesper --lib
cargo test --locked -p hesper --test demo
cargo test --locked -p hesper --test apple1
make verify
cargo build --locked -p hesper --release
make wozmon-tests ROM=/absolute/path/to/wozmon.bin
git diff --check
```

`make verify` 必须涵盖 debug/release workspace 测试、fmt/check/Clippy 和显式 demo，不能省略 release。新测试如在新增 target 中，还需运行该 target。

先使用已有可用 ROM 和用户提供的路径；普通实现、构建、测试不触发下载。没有真实 ROM 时继续完成原创测试和界面功能，把真实 ROM/PTY 项列为未验证，不能称为全部完成。

只改变 CLI 时，不要求重新下载完整 CPU 外部语料。若实际修改 CPU timing/pins/RESET 或机器硬件语义，另列变更原因，并执行对应 focused/外部验证；原始预期不能为通过测试而重生成。

仅修改 Makefile 的 demo 命令不要求运行网络工具回归。改到工具脚本时才运行相应 `make tools-test` 或聚焦测试，并明确其是否联网。

在 `docs/verification.md` 追加：日期、HEAD/工作区说明、实际命令及结果、ROM 指纹、P01–P16 状态、截图/转录位置、已知限制。截图和大转录放忽略缓存（如 `.cache/tui-qa/`），不提交 ROM 或个人配置。计划中的通过标准不能复制成已完成证据。

交付时明确区分：源码完成、编译通过、自动化测试通过、真实终端验收、提交、推送、远程 CI、发布。本任务默认只做到本地 review 交付。

```text
完成范围：
```

## 16. 完成定义

只有以下条件同时成立，才能把本任务标为完成：

- 无参数双 TTY 能完成选择、配置、启动、操作、返回和继续的完整流程。
- 所有首版菜单与快捷键有实际行为；帮助、footer 和实现一致。
- Apple-1 屏幕、外围状态、提示和输入焦点正确隔离。
- 真正的机器状态被正确保留、复位和重建；没有以 UI 文本冒充执行结果。
- 旧脚本入口、预算、trace、错误通道以及自动化门禁保持可用。
- 中文、紧凑窗口、单色/ASCII 和终端清理通过对应验证。
- 规定的自动化测试与真实 ROM/终端验收有实际证据；缺失项不会被标为通过。
- 用户收到可 review 的 diff、证据、已知限制和明确的本地交付状态。
